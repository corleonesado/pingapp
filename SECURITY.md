# SECURITY

The security posture of pingapp, in one page.

## Threat model

The relevant adversaries for this project are: an opportunistic attacker scraping public registries and repos for secrets or vulnerable images, a supply-chain attacker shipping a compromised dependency, and an internal mistake that publishes a credential. Out of scope: targeted attackers, the host laptop's OS, and the security of the cloudflared edge. The trust boundary is the container image: anything inside the binary plus the distroless base is what we defend; the cluster around it is treated as friendly.

## Image & runtime hardening

- Base image: `gcr.io/distroless/static:nonroot` — no shell, no package manager, no userland tools.
- Runs as **UID 65532** (`runAsNonRoot: true`); never root.
- `readOnlyRootFilesystem: true`, `allowPrivilegeEscalation: false`.
- All Linux capabilities dropped (`capabilities.drop: ["ALL"]`).
- `seccompProfile.type: RuntimeDefault`.
- The pod spec also pins `fsGroup: 65532` so writable volumes (none today) would be group-owned by the same non-root identity.
- Probes hit `/healthz`. `/ping` is human-only and `/metrics` lives behind the cluster (no public ingress route).

## Image scanning (the gate)

Trivy scans every build in CI **and** every release, failing on **HIGH/CRITICAL** with `--ignore-unfixed`. Details and rationale in [ADR-0004](docs/decisions/0004-image-scanning-gate.md). The gate has already caught a real finding: stale Go stdlib CVEs in `golang:1.22-alpine` were fixed by bumping the build toolchain to `golang:1.26-alpine`. **Disabling the step is not allowed**; fix the root cause (bump base / pin a patched dependency).

## Supply chain

- The release workflow attaches a **CycloneDX/SPDX SBOM** (`pingapp-<version>.spdx.json`) generated by Syft, listing every Go module and OS package shipped in the image.
- All container layers are pulled from upstream registries (`gcr.io/distroless`, `golang` on Docker Hub); no private mirrors.
- Image tags are **immutable**: CI pushes `:<sha>`, the release pushes `:<sha>` + `:<semver>`. There are **no `:latest` tags** anywhere — manifests, compose, Helm values — and the chart's `imagePullPolicy: IfNotPresent` makes accidental drift impossible.
- All third-party GitHub Actions are pinned to a specific tag (see `.github/workflows/*.yml`).

## Secret handling

- **No secrets in Git, ever.** `gitleaks` scans full history on every PR and push; if it fails, the leaked credential must be rotated, not just removed.
- The only application-relevant secret is the read-only PAT ArgoCD uses to fetch the private repo. It lives in `kubernetes.io/Opaque` Secret `pingapp-repo` (namespace `argocd`), populated via `stty -echo` + heredoc (see RUNBOOK). The token has **`Contents: read` only**, scoped to a single repo, with a finite expiration.
- GHCR pushes use the workflow's built-in `${{ secrets.GITHUB_TOKEN }}` — **no long-lived PATs in CI**.
- `.env` is gitignored; only `.env.example` is tracked.

## Cluster / network

- Ingress is the only externally reachable surface inside the cluster; `NodePort` is dev-only.
- The public URL (cloudflared quick tunnel — [ADR-0005](docs/decisions/0005-public-url-cloudflared.md)) is an **outbound** dial from the laptop; no inbound ports are opened on the host or router.
- PodDisruptionBudget keeps prod at `minAvailable: 1` so a node drain or rollout can never zero the service.

## Vulnerability reporting

This is a four-day case study, not a maintained product. If you spot something exploitable in the demo, email me directly at **sadettin.er@sabanciuniv.edu** — please don't open a public issue. I will respond within 48h and rotate any affected credentials immediately.

## Known limitations (kept deliberately for scope)

- Repo and image are reachable by anyone with the link during the demo window; the GHCR package is public so ArgoCD can pull without a registry secret.
- The cloudflared **quick** tunnel is anonymous and unauthenticated — anyone with the URL can call `/ping`, `/version`, `/healthz`, `/metrics`, and `/chaos`. The endpoints return no sensitive data; the worst a stranger can do is trigger the synthetic 500.
- The cluster has no NetworkPolicy yet; pingapp would accept connections from any pod in the namespace. Listed in the bonus track.
